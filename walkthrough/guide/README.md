# AutoLedger test guide

This guide walks every shipped feature of AutoLedger, one module at a time. Each section tells you where to click,
what you should see, and ends with a **Try to break it** list of things the product must refuse — with the refusal
it should show. Tick the box at the end of each section as you go.

The guide is generated by `npm run walkthrough` from templates in `server/src/scripts/walkthroughGuide/`; do not edit
the files in this folder by hand.

## 1. Start the app with the demo company

1. From the repository root run `./dev.sh`. It starts Postgres and Redis, applies migrations, then runs the server
   (port 5000), the worker and the client (port 5173).
2. In a second terminal: `cd server && npm run db:reset && npm run seed:demo`. The seeder replays the seven
   walkthrough months through the real API and ends with `Demo organization "Harbor Point Fabrication" is ready.`
3. Open `http://localhost:5173` and sign in as `demo@autoledger.dev` with password `autoledger-demo`. If
   `VITE_DEMO_EMAIL` and `VITE_DEMO_PASSWORD` are set in `client/.env`, the sign-in page also shows an
   **Explore the demo company** card with an **Open the demo** button.
4. Optional but recommended: `cd server && npm run verify:integrity` — every check should pass.

The demo's books are the walkthrough's answer key: seven months, March to September. Anything that posts,
voids, pays or locks changes those figures. Such steps are marked **⚠ scratch org** in the guide.

## 2. Make a scratch organization

Create a second organization to hold every destructive step: open the organization menu in the top bar and choose
**Add organization**, then finish its setup wizard. Switch between the demo and the scratch organization from the
same menu. Use the scratch organization for every step marked **⚠ scratch org**.

## 3. Optional services

Most of the guide needs nothing but the stack above. These sections need an external service; skip them if you do
not have it. Restart the server **and** the worker after changing `server/.env`.

| Service | What it unlocks | How to turn it on |
|---|---|---|
| Mailpit (local inbox) | Reading the emails the product sends (invitations, password reset, statements) | `docker compose --profile mail up -d mailpit`, set `MAIL_TRANSPORT=mailpit`, restart the server and the worker, open `http://localhost:8025` |
| Stripe test mode | Paying a statement by card | `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET` (test keys only) |
| Vision model key | Bill inbox extraction | `ANTHROPIC_API_KEY`, or `CAPTURE_AI_PROVIDER=gemini` with `GEMINI_API_KEY` |
| Google Drive | Folder intake | `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` |
| Email-in | A per-organization address for the bill inbox | `INBOUND_MAIL=brevo`, `INBOUND_MAIL_DOMAIN`, `INBOUND_MAIL_WEBHOOK_SECRET` |

With the default `MAIL_TRANSPORT=log` no email leaves the machine: the message, including any link, is written to
the worker's log.

## 5. Suggested order

1. Sign in and look around: guides 01 and 03.
2. Read the books without changing them: 04, then 14.
3. Switch to the scratch organization and do the posting guides: 05, 06, 07, 09, 10, 11.
4. Set up people and structure: 02, 12, 13, 16.
5. Finish with 15 and the optional 08.

Month 7 of the walkthrough itself (`11-currency-tax-and-journals.md` in the parent folder) covers the euro customer,
sales tax and journals as a scored scenario; these guides cover the same features as a checklist.
